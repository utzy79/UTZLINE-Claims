# UTZLINE Progress Claims — installable app

**Current version: v5 (RC 1.0)** (its own independent version line — bump this line and the service worker's `CACHE_NAME`, and add a dated entry below, every time a new build ships.)

**v5 (2026-10-10): tables.** (Andrew: "all tables need to be sortable, selectable columns"; Progress Claims "full width of screen".) The claim table is the full width of the screen, every column can be ticked on / off and moved (Columns menu, remembered per device), and a tap on any heading sorts the lines within each level (ascending, descending, original order); level totals and the shop drawings line stay in place. The Approved columns are always in the list (blank until the claim is submitted).

**v4 (2026-10-10): zones are not levels.** A level that UTZLINE Projects split over several floor plans ("LEVEL 1 (H1a)", "LEVEL 1 (H1b)") is ONE level in the claim: one level heading and total, shop drawings claimed once per level, the level filter lists it once; the plan's zone fills the Zone column when the item has none. Nothing on disk changes: items keep the plan's name as their level, folders stay as they are.

**v3 (2026-10-10):** its own colour (Andrew: *"those 4 new apps are using colours already used"*): green (#79d13f, day #3f7f17) -- no other UTZLINE app uses it. The whole palette follows (night and day backgrounds, panels, borders, buttons with readable text, the theme colour), the icon (drawn in the colour's own brightness, not only its hue) and the PDF / Excel header rule. Made with `build-tools/recolour_app.py`.

**v2 (2026-10-09):** shared app-shell update only (the project's manager is read with the project, for the Dashboard). No change on screen.

**v1 (2026-10-09):** a new app. Andrew: *"stage weights, but also editable per item, we may claim an amount but it gets reduced at approval so this needs to be adjustable (each claim needs an approved on last claim amount, this can be a percent or dollar value / one changes the other) also need retention and gst"*, laid out as his *Progress Claim Breakdown* (MBH, October).

- **The claim sheet, as his:** per level, every joinery item from UTZLINE Projects — Zone, Area (from the room number, e.g. "RD" from "RD.029"), Sub Area (the room), Joinery Code, Description, WO#, Drawing No., Qty, Original Quote, Quote × Qty, Shop Drawings Complete, **Value** (quote × qty less the shop drawing share) — then the level's **SHOP DRAWINGS (10%)** line and its **TOTAL**; then the **Variations** (every approved variation from Variations & RFIs, at its approved value less credit) and their total; then **Project Totals**: this claim value, less retention, net, GST, **amount due**; and beside it what was approved before this claim (retention, net, GST, paid to date).
- **The quote** is the item's *Dollar value* from UTZLINE Projects (qty 1). Tap an item's code to set its zone, area, drawing no., shop drawings complete (automatic = a shop drawing has been sent in the Viewer, or yes / no by hand), qty and quote (qty / quote change the contract value: administrator PIN).
- **Every line:** approved prior % and $, **this claim % and $** (type either — the other follows), total % including this claim, remaining %.
- **Stage weights** (Claim settings): how much of an item's value is earned at each status — Check measured 5%, In manufacture 15%, Cut 30%, Machined 45%, Ready to inspect 55%, Ready to dispatch 65%, Delivered 85%, Installed 100% (change them for the project). **Fill from stage weights** puts on every line what its status has earned less what was approved before; the shop drawings line takes the share of the level whose shop drawings are complete. Any line can then be changed by hand.
- **Approval:** *Mark submitted* locks the claimed figures and opens the **approved % / $** boxes: type what the builder approved on any line they reduced (a line left alone is approved as claimed); **Mark approved** (administrator PIN) writes the approval. The next claim's *approved prior* is what was approved (a claim still waiting counts at what it claimed). *Reopen* (administrator PIN) goes back one step; only the latest claim can be reopened.
- **Claim settings** (administrator PIN): shop drawing %, retention %, GST %, stage weights, payment terms, claim to.
- **Cards and bars:** contract value, approved before, this claim, retention, net, GST, amount due, approved this claim, % complete; a bar per level (approved prior + this claim of the level's value).
- **Print (PDF)** — the claim sheet (A3 landscape, the shared header with the company and builder logos at half size) with the Project Totals under it; **Export Excel** — the claim sheet, *Project Totals*, and a *Summary* sheet (per level: contract value, approved prior, this claim, remaining, % complete, shop drawings value and claimed) like his Charts tab.
- **Where it keeps things:** `<Project>\Project Saves\Progress Claims\Settings\` (settings, item details) and `Claim 01\`, `Claim 02\` … (`create`, `claimed`, `approved`, `status`) — one small file per change (lines typed together go in one file), never overwritten, never deleted. Statuses are read from the Joinery Status events (`shared/job-status`), never written.
- Sign-in at the start (app code **ProgressClaims** in the Users screen — tick it only for the people who do the claims), Change folder needs an administrator PIN, works offline.
